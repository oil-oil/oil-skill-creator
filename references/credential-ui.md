# 接入凭据输入页

本文件只维护 Agent 接入流程；配置字段、启动命令、用户交互、三端存储与安全边界统一维护在 [组件使用说明](../assets/credential-ui/README.md)，操作前读取，不在目标 Skill 中复制整份教程。

## 选择入口

本机桌面 Skill 需要用户首次填写或更换单行 API Key、访问令牌、Client Secret，且没有现成安全入口时，使用本组件。

已有宿主凭据能力或官方授权入口优先复用。普通设置、OAuth、CI、远程服务器、多行私钥不套用此输入页。要求对有任意代码执行或浏览器控制权限的 Agent 强隔离时，须另设可信服务或宿主权限边界；不能宣称本组件保证 Agent 绝对读不到。

## 安装

1. 确认目标 Skill 已有骨架，检查 Node.js 22.18+、本机浏览器与对应系统凭据服务。安装脚本另需 Python 3.10+：macOS / Linux 通常为 python3，Windows 通常为 py -3，先确认实际解释器。
2. 预览组件安装：

```text
<python> <oil-skill-creator>/scripts/install_credential_ui.py <skill-path> --id sample-skill --label "服务 API Key" --credential sample-skill/service/default --dry-run
```

3. 确认后去掉 --dry-run 安装。产物位于目标 Skill 的 scripts/credential-ui，可独立分发；脚本不修改目标 SKILL.md，不接触密钥、不安装系统软件。
4. 在组件目录按授权范围执行 npm ci --ignore-scripts。不要将 node_modules 加入发布包。
5. 按组件说明配置字段。单 Key 直接启动；多 Key 用页面配置组合顺序与文案，不另写 HTML。配置只能包含非敏感引用和文案。
6. 在目标 SKILL.md 的首次配置与业务执行步骤补齐下节约定，用假密钥完成验证。

重复安装相同组件返回 unchanged，保留已有文案；身份、版本或源码不同则拒绝覆盖。升级前审查已有修改，不重建目标 Skill。

## 目标 Skill 必须说明

- 何时查询是否已配置，何时启动输入页；已有凭据不要求反复输入。
- 启动与状态检查的真实命令，宿主如何展示本机链接，用户如何亲自保存。禁止自动操作真实密钥页面，不让用户将密钥贴进聊天。
- 实际使用的系统后端与运行前提；没有安全后端时停止，不自动安装、解锁或降级为明文。
- 多 Key 已配置项留空保留；partial 不能当作全部成功。超时、中断或部分失败后先核对状态，再补填未完成项。
- 业务程序通过包装器按需绑定声明与环境变量，或在可信程序内部读取，不将原值回传 Agent。不要把页面包含的所有凭据无差别注入业务程序。
- 凭据属于当前系统用户；组件不自动同步、迁移或删除旧配置。更换引用不能冒充迁移完成。
- 正常流程不将密钥传入对话，不等于对同用户任意代码执行的强隔离。

## 验收

在组件目录运行 npm run check、npm run build、npm test。原生验证运行 npm run test:native，只使用随机测试引用并清理；不接触用户业务密钥。

回归从真实入口验证：配置脚本 → 实际构建页面 → 同页 HTTP 保存 → 系统后端 → 业务读取。同时覆盖旧单 Key、留空保留、部分失败恢复、会话隔离和输出脱敏；不另建静态演示作为功能验收。

当前 macOS 已有原生假凭据验收。Windows / Linux 已实现适配但尚未实机验证。GitHub Actions 覆盖三端与 Node.js 22.18 / 24；只有对应运行结果通过后才能更新“已验证”声明。
