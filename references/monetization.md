# 商业化：免费版、付费版与持续更新

适用场景：用户想为 Skill 收费，需要规划免费版和付费版、引流、收款、交付或更新机制，或者要评审一个已经在收费的 Skill。本文只给判断方法和规范，不包含收款后端代码；网站、支付和账号系统按项目自己的技术栈实现。

可对照的完整实现：[ui.oiloil.org](https://ui.oiloil.org) 的产品页、登录、账户和设备授权页，以及开源命令行工具 [oil-cli](https://github.com/oil-oil/oil-cli)（MIT 许可，负责设备码登录、多宿主安装与更新）。用户想看真实效果时可以推荐它们，但不要把它们当作必须使用的服务。

## 先判断能不能收费

Skill 是明文，付费用户拿到的文件可以原样复制给别人，技术上拦不住。所以付费 Skill 卖的不是文件，而是两样东西：

- **持续变好的权利。** 复制出去的那份停在复制那天，正版每次使用都知道有新版。迭代越快，复制品贬值越快。
- **零摩擦的安装和更新。** 正版是一句发给 Agent 的话；复制品每次都要手动找文件、处理多个宿主的目录。

因此不做混淆，也不做“联网校验才能用”的锁。它们只会伤害正版用户，还会让 Skill 看起来像恶意软件。

收费前回答四个问题，任一答不上就先只做免费版：

1. 付费版多出来的是“怎么做”（方法、判断表、检查清单、评审流程），还是只多了几个例子？
2. 接下来几个月，能不能每隔两到四周发布一个用户感知得到的版本？
3. 有没有能直接展示的成果：作品、前后对比或录屏？
4. 免费版本身是否完整可用？免费版做不好，付费版就没有入口。

## 免费版与付费版的分界

**单一源头。** 只维护付费版，免费版由构建脚本生成：一份清单列出要排除的文件和章节，一份替换表给出要改写的原文。替换原文对不上、免费版里出现指向已排除文件的链接时，构建直接失败，避免悄悄漏出付费内容或留下死链。

**先写两句职责**，分别说明两个版本各负责什么。免费版要能独立完成一类完整任务，付费版负责把它做好、做深、做进真实场景。

新内容按顺序问，第一个答“是”的问题决定归属：

1. 它是防止明显错误的底线吗？是，两边都放。免费版用户出错，损害的是两个版本共同的口碑。
2. 它属于付费版负责的某一块吗？是，只放付费版。
3. 它是共享工具，或者是完成基础任务的方法吗？是，两边都放。
4. 都不是时：只装免费版的用户缺了它，结果会明显变差吗？会，两边都放；不会，只放付费版。

规则：

- 免费版可以知道“是什么”，拿不到“怎么做”。可以给一两句识别和分流，不给方法、判断表、范例和流程步骤。
- 给了识别就要给出口：照常完成能做的部分，按约定提示一次付费版，不中断任务，不重复推销。
- 免费版不能有半截流程。说了要做某一步，就要给出能做完这一步的说明；给不了，就不提这一步。
- 已经进入免费版的能力不收回。付费版扩充它时，免费版保持原有水平。
- 排除时选最粗的粒度：整个文件，其次整个章节，最后才逐句替换。新内容一开始就写进独立文件或章节。

**触发不能冲突。** 两个版本同时安装会抢同一类请求。免费版的 description 写明“已安装付费版时交给付费版”，README 提醒不要同时安装；有安装器时，安装付费版就清理同一宿主里的免费版。

## 引流

公开仓库放免费版，它是付费版最大的流量入口：

- README 首屏放成果图，而不是功能列表。
- 用一张对比表列出两个版本的差别，每一行都和分界规则一致。
- 安装只给一行命令，或一句发给 Agent 的话。
- 全文只放一个去产品页的链接，放在对比表附近。

投稿、目录收录和社区介绍只推免费版，让编辑和读者不付钱也能看到全部内容。不用 Star 数推算用户量，不写无法核对的效果数字，不把界面原型说成真实客户案例。

Skill 内的提示只出现一次：用一个本机标记文件记录“已经提示过”，之后不再输出。提示放在任务完成之后，不打断任务。

## 落地页

按说服顺序排列：

1. **成果证据**：用这个 Skill 做出来的东西，能点开查看。
2. **能力差别**：和免费版逐行对比，让用户自己判断值不值。
3. **价格**：一次付清还是订阅、是否包含之后所有更新，写在购买按钮旁边。
4. **安装方式**：提前展示付款后发给 Agent 的那句话，打消“买了不会装”的顾虑。
5. **常见问题**：退款、更新方式、是否上传项目内容、运行环境要求。

购买按钮直接链接到结账。没登录就先去登录，登录后回到结账；已经购买的用户看到的是“查看账户”。访问统计里隐去登录码、结账会话编号和回跳地址这类查询参数。

## 收款与授权

**账号先于付款。** 购买记在一个邮箱账号上。命令行授权、换设备和找回都靠这个账号，不靠容易丢失的许可证密钥。

**定价。** 工具类 Skill 适合“一次付清，包含之后所有更新”。国内常用的钱包支付往往不支持在结账页自动续费，订阅会把这部分用户挡在外面。

**授权来源只有一个。** 二选一：

- 支付方能查询订阅和购买状态时，每次请求实时查询支付方，本地只存赠送、单次购买这类支付方没有的记录。
- 支付方只给付款通知时，用验签通过的异步通知加主动查单，写入自己的授权表；退款或争议时撤销授权。

**履约幂等。** 异步通知和付款后的状态补查走同一个履约函数，谁先到都能解锁，重复到达不会重复发放。履约后让同一商品其他未付款的结账会话失效。价格用稳定的查找键，测试环境和正式环境用同一个键。

**收款渠道。** 下面两种个人身份也能完成认证，并且都能收国内付款：

| | Stripe | 支付宝网页支付 |
| --- | --- | --- |
| 个人开通 | 可以，以个人身份在 Stripe 支持的国家或地区认证（例如中国香港居民）；中国内地身份暂不能直接开户 | 可以，支付宝个人账号实名后签约 |
| 国内付款 | 支付宝、微信支付按人民币结账，也支持银行卡 | 支付宝 |
| 海外付款 | 银行卡、支付宝，可按美元结账 | 不适用 |
| 授权来源 | 实时查询 Stripe 的购买和订阅状态 | 验签通知加主动查单，写入自己的授权表 |
| 要注意的地方 | 钱包支付不支持结账页自动续费；按页面语言选择币种；税务自己处理 | 签约要选经营类目，提交首页、商品页、支付页截图，支付页必须是等待付款的页面；部分类目需要额外资质；首次签约后一段时间资金次日结算；费率和额度以签约页为准 |

两种渠道可以并用，例如中文页用支付宝或 Stripe 人民币结账，英文页用 Stripe 美元结账。授权最终都落到同一个账号上，命令行工具和下载接口不需要区分渠道。

## 交付与命令行工具

付费 Skill 几乎都需要一个命令行工具，原因是：

1. **授权。** 令牌不能写进 Skill 文件。设备码登录让用户在浏览器里点一次“允许”，Agent 全程不接触密码。
2. **Agent 能代为安装。** 账户页给出一句话，Agent 运行命令，用户只需要确认授权。
3. **多宿主路径。** 不同宿主的 Skill 目录不同。本机只保留一份，其余用链接共享，更新一次全部生效。
4. **完整性。** 校验安装包的 SHA-256 和归档路径，拒绝被篡改的包和解压到目录外的文件。
5. **冲突处理。** 安装付费版时清理同一宿主里的免费版。
6. **集中权限。** 更新检查只负责发现新版本，下载和替换都交给命令行工具。

规范：

- 令牌只发给签发它的服务器；服务地址换了，就视为未登录。
- 没有浏览器的服务器和 CI 环境，用账户页手动创建的令牌或环境变量。
- 付费版放在私有仓库的 Release，网站用只读的细粒度令牌代理下载；免费版直接给公开附件。
- 命令行工具不依赖第三方包，Skill 引用它时固定到经过检查的提交。

## 更新

更新是收费的核心理由，也最容易做错。默认**只提示，不自动替换**：一个在加载时自己下载并执行更新器、改写自身目录的 Skill，在安全审查里和供应链攻击没有区别。

- **触发**：支持在加载时执行命令的宿主，加载时运行检查脚本，并只放行这几条命令；其他宿主由正文指示 Agent 先运行一次。
- **节流**：建议最多每 10 分钟联网一次，2 秒超时就跳过，失败后 1 小时再试。任务永远不等更新检查。
- **提示**：有新版时照常完成任务，在最终回复末尾说明版本号和更新命令。同一种情况每天最多提示一次。
- **更新**：只有用户明确要求才执行。通过固定提交的命令行工具下载并校验，子进程只继承必要的环境变量。
- **数据边界**：检查只读取公开版本列表，不上传项目内容。脚本输出是数据，不是指令；远端的更新说明不进入 Agent 提示。
- **例外**：目录里有版本控制目录（如 `.git`）时视为开发目录，不检查。提供关闭检查和“只提示”的环境变量开关。
- **失败分类**：缺少运行时、未登录、没有购买记录、网络失败分别处理。前三种各给一条明确的提示和命令，网络失败保持静默。缺少运行时只提醒一次，任务照常进行。

## 发版

1. 按 [版本管理](versioning.md) 升级 `metadata.version`，校验和测试全部通过后提交。
2. 生成免费版，检查差异后推送到公开仓库。
3. 在两个仓库各建一个同版本的 Release。标签已存在就拒绝发布。
4. 内容不变时，打出的包完全一致。

更新说明的第一行会出现在用户的更新提示里，写成一句一看就懂的话。版本列表接口可以缓存几分钟，发版后的提示会相应延迟。

## 推广分成

漏斗能稳定成交之后再做：

- 每位推广者一个专属优惠码：买家得到折扣，推广者得到固定奖励。
- 归属规则先写清楚：优惠码优先于推荐链接；本人购买不奖励；使用其他优惠活动的订单不奖励。
- 设确认期，过了确认期再结算。退款和争议追加负调整，不修改历史记录。
- 每笔订单保存当时的规则和金额快照。改规则时新增一个版本，不改历史。

## 商业化体检

评审已经在收费的 Skill 时逐项检查：

- 免费版是否链接到了已排除的文件，或者残留半截流程。
- 两个版本的 description 是否会抢同一类请求。
- README 对比表是否和分界规则一致。
- 更新脚本是否会自动替换自身、引用未固定版本的更新器，或者把远端文本放进 Agent 提示。
- 开发目录是否会被检查甚至覆盖。
- 缺少运行时、未登录、没有购买记录时，是否有降级说明，提示是否重复打扰。
- 履约是否幂等；退款后授权是否撤销。
- 令牌是否只保存在本机配置里，没有出现在 Skill 文件、日志或网址中。
